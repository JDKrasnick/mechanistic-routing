00 — HYPOTHESIS

What is actually being tested

Project claim

A candidate-level counterfactual critic can predict the held-out marginal utility, cost, and interaction effects of proposed textual, activation-level, and parameter-level interventions — enabling budget-constrained heterogeneous adaptation without exhaustively executing every candidate update.

That claim only means something if it can fail. The baseline is built so that three specific things could go wrong, and each is measured directly rather than asserted.

Prediction 1 · Heterogeneity
Different states are best served by different intervention types. If one type always wins, routing is unnecessary and the premise collapses. Measured as oracle winner share by type.
Prediction 2 · Learnability
Utility is predictable from pre-execution features alone. The critic must beat a static type prior — not just random — on within-state pairwise ranking accuracy.
Prediction 3 · Efficiency
Critic routing approaches oracle utility at a fraction of execution cost. Measured as task gain vs exploration cost, with the oracle paying for all 9 candidates and the critic for 1.
Prediction 4 · Retention
Cheap-but-damaging updates are avoidable. Utility penalizes retention loss, so a candidate that wins on task accuracy while degrading general capability must not be selected.
The load-bearing design decision

propose() is cheap and produces only a specification. apply() is expensive and realizes it — training a LoRA, fitting a steering vector. This split is the entire efficiency argument: the critic ranks specifications, so it never pays for the candidates it rejects.

Verified — state restoration is exact

Reverting any intervention restores logits bitwise (max |Δ| = 0.00e+00), including after stacking all three types and restoring. LoRA is a hand-rolled module swap holding a reference to the original nn.Linear — nothing is ever merged into base weights, so repeated apply/revert cannot drift.

This gate caught a real bug: candidates applied via candidate.apply() instead of the tracked stack leaked steering hooks into the next trial, which would have silently contaminated every downstream measurement.

02 — INTERVENTIONS

Three levers, calibrated

Each type was swept independently to find where it helps and where it hurts. The candidate grids deliberately span both regimes — avoiding a damaging update is half of what routing is for.

Two magnitude bugs this sweep caught

Steering was a no-op. The difference-in-means vector was being unit-normalized before scaling. Residual-stream norms at these layers are 60–155, so a unit vector contributed essentially nothing. Keeping the raw scale turned a flat 0.000 into +0.150.

LoRA was undertrained, then overtrained. The initial grid capped at 16 steps × 1e-4 and moved nothing. Widening it exposed a sharp optimum — and the fact that driving training loss to zero on a 12-example failure batch actively destroys held-out accuracy.

Why evaluation is one forward pass

Scores come from the logits of each label word's first token at the final position — never from generation. Label first-tokens are asserted collision-free at startup. A full evaluation is therefore 64 forward passes and ~15 seconds, which is what makes several hundred counterfactual measurements feasible on a laptop GPU.

Prompt format was chosen by measurement, not taste: raw completion beat a chat template with a system message on all three axes — accuracy (0.605 vs 0.595), sequence length (68 vs 94 tokens), and calibration (gold log-prob −2.79 vs −3.66).

Split hygiene

Failure batches that drive candidate generation are drawn from the train split; every reported score comes from validation. Routing episodes use seeds disjoint from the critic's training states, and end on a larger fixed evaluation batch that no policy optimizes against.

Leak guard

Fitted steering-vector norms, final LoRA training loss, and every post_* measurement are recorded in the dataset for analysis but are on an explicit FORBIDDEN list and cannot reach the model. Using them would leak the very outcome the critic is meant to predict, and would make every headline number meaningless.

Two heads, per the project plan. Regression (gradient boosting) gives a calibrated absolute utility — required for budget arithmetic and for the policy to decline when nothing is worth applying. Pairwise ranking (logistic on within-state feature differences) gives the ordering that selection actually consumes, invariant to per-state shifts. A third head predicts squared residual, for uncertainty.

05 — ROUTING

Seven policies, matched budgets

All policies start each episode from the same state, see the same candidate set, and are scored on the same held-out batch. Only the routing decision differs.

PolicyDecision ruleExecutes
prompt_onlyrandom prompt candidate1
activation_onlyrandom steering candidate1
lora_onlyrandom adapter candidate1
randomuniform over affordable1
heuristicbest type by training mean, cheapest within it1
criticargmax predicted utility − λ·cost; may decline1
oraclemeasured best under budget9
Why the heuristic is a static type prior

It always picks the intervention type with the best average training utility. That captures everything a fixed preference order can express — so any margin the critic gains over it is attributable specifically to state-dependent routing, which is the actual claim.

One asymmetry is disclosed rather than hidden: only the critic and the oracle can decline to act, because only they have a utility estimate. Type usage per policy is reported so this is visible in the results.

Known risks to the result

Target noise. Task batches are 40 examples, so one flipped example is 0.025 utility. Evaluation is paired (same examples before and after), which cuts variance on the difference substantially, but small true effects will still be hard to rank and this caps achievable Spearman.

Scale. 30 states × 9 candidates is enough for a 36-feature model with grouped CV, but it is a baseline, not a converged result. Interaction prediction and uncertainty (step 8 of the plan) need more states.

Single task pair. Heterogeneity is demonstrated on emotion → ag_news. Whether the learned routing policy transfers across task families is out of scope here.
