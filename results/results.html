Candidate-level counterfactual critic · Qwen2.5-3B-Instruct · emotion → ag_news · 30 states, 270 counterfactuals, 7 routing policies

The Question

Can a critic predict which intervention will help — before running any of them?

When an LLM is failing you can fix it three ways: edit the prompt, steer activations, or train a LoRA. You don't know which works without trying all of them, and trying all of them is expensive. This experiment tests whether a learned critic can predict each candidate's held-out utility from cheap features, well enough to route to the right one and skip the rest.

The claim breaks into four sub-questions. Three hold cleanly; one holds with a caveat worth stating.

Prediction 1 · Heterogeneity

Do different situations need different intervention types?Yes

If one type always won, routing would be pointless. Across 30 states, the best candidate was split near-evenly — prompt 40%, activation 30%, LoRA 30%. No type dominates, so choosing is a real decision.

Also telling: ~75% of all candidates hurt (mean utility negative for every type). This task is mostly about avoiding damage, not finding wins — which shapes how to read the critic's value below.

Prediction 2 · Learnability

Is utility predictable from pre-execution features alone?Yes

The critic sees only what's knowable before running a candidate: baseline scores, failure statistics, candidate hyperparameters. It must beat a static type prior ("always pick the historically-best type"), not just random.

Prediction 4 · Retention

Does it avoid updates that break general capability?Yes, with caveat

Utility penalizes retention loss, so the critic should reject candidates that buy task accuracy by damaging the model. Critic retention 0.669 beats random (0.538) and all single-type policies (0.48–0.55); only the oracle is higher (0.688).

Caveat: the retention task is scored with the system's current instruction, so a prompt tuned for emotion also gets applied to news. Prompt "retention loss" is partly task-specialization; activation/LoRA loss is genuine capability damage. It's one number measuring two different things — deliberate (a single shared prompt is realistic) but worth stating plainly.

General Result

A candidate-level critic predicts held-out intervention utility well enough to route heterogeneous updates at ~1/23 the cost of exhaustive search — recovering 78% of oracle gain and most of its retention protection.

Much of that value comes from declining harmful candidates, which dominate the pool, rather than from precisely spotting the single best win. That's a real and useful result, but a narrower claim than "knows which update helps."

What To Do Next

  1. Scale the dataset. 30 states is thin for a 36-feature model. 150–300 states would tighten the noise-limited Spearman ceiling and make the interaction terms (lora×low-acc, act×depth) actually estimable rather than decorative.
  2. Cut evaluation noise. 40-example batches make one flipped label worth 0.025 utility. Larger held-out batches, or the already-recorded low-variance signals (gold log-prob, margin) as regression targets, would raise the achievable ceiling.
  3. Test the interaction claim directly. The project's headline mentions interaction effects, but the current run only weakly probes them. Collect at deeper stacks (3–4 interventions) and measure whether the critic predicts composed utility better than the sum of marginals.
  4. Activate the uncertainty head. The critic already predicts its own error variance but nothing uses it. Add risk-averse selection (predicted utility − λ·std) and measure whether it further cuts the rate of harmful picks.
  5. Separate the two retention signals. Score retention with a fixed neutral instruction so prompt-specialization and true capability damage are measured independently.
  6. Add a second task family. One extra target/retention pair (e.g. a reasoning or QA task) is the cheapest test of whether the routing policy generalizes at all.
